Smart Navy AI · Hearts of Iron IV · Paradox script

It stops sailing into the Channel.

A mod for the Hearts of Iron IV AI. It tells each major power which water it can survive in and which it cannot, and it makes ship design react to what intelligence actually knows about the enemy fleet instead of following a fixed script.

The problem

Two ways the naval AI loses

Both are fixable from script. Neither needs a stat buff.

OneGeography

Vanilla does know Germany should stay out of the English Channel. GER.txt ships a plan called axis_stay_away_from_the_royal_navy that avoids it at weight 600. The idea is right. The gating is what fails:

# vanilla common/ai_strategy/GER.txt
enable = {
    date < 1942.1.1
    OR = {
        GER = { naval_strength_ratio = { tag = ENG ratio < 0.5 } }
        ... thirteen divisions_in_state checks ...
    }
}
abort_when_not_enabled = yes

Two switches turn it off exactly when it is still needed. On 1 January 1942 the plan aborts and never returns — every convoy routed after that date is routed with no penalty on the Channel or the Western Approaches, which is where the Royal Navy and its submarines live for the rest of the game. And it only holds while the Kriegsmarine is under half the Royal Navy; a Germany that builds up crosses 0.5, the plan aborts, and the fleet walks into the Home Fleet.

Japan is worse. Its entire file contains one naval mission strategy, and it makes Japan escort less. That one is correct on its own terms — nobody is raiding Japan in 1940, so escorting is wasted fuel — and the mod leaves it alone. The problem is that it aborts on war with the United States and nothing replaces it. At the moment the largest submarine campaign of the war opens against the one sea lane Japan cannot live without, Japan's scripted naval priorities are empty.

TwoArithmetic

Naval gunnery resolves through a piercing-to-armour ratio, and the AI builds to a fixed template that has no idea what it is shooting at. Get the ratio wrong and a battleship does a tenth of its printed damage — the gun fires, the numbers scroll past, and nothing sinks.

The mod reads the enemy's numbers through estimated_intel_max_armor and estimated_intel_max_piercing, which report armour and piercing as estimated from intelligence. A country with no intel network sees nothing and keeps building what it was building. A country that has done the work designs against the real fleet. Vanilla already uses this idiom — but only for tanks. Never for ships.

Consequence one

Light attack cannot hurt armour

The best light battery pierces 2.5. Against the thinnest cruiser belt that is a ratio of 0.42 — the 0.30 band. Against a battleship it is 0.08, the 0.10 band. Light attack is for killing unarmoured screens, and it is superb at that, but a light-attack fleet cannot sink a capital ship.

Consequence two

The gun ladder runs out

The heaviest gun pierces 45. Super-heavy armour is 55. Nothing in the game reaches ratio 1.0 against it — the best case is 0.82. So the answer to a super-heavy enemy is not a bigger gun, because there isn't one. It is torpedoes, which skip the piercing table entirely.

Consequence three

Armour is bought in bands

To drop an attacker from 1.00 to 0.70 you need armour above their piercing. To reach 0.40, above their piercing divided by 0.75. Tonnage spent between those points buys nothing at all — it is speed and cost for no protection.

Consequence four

Screens are the real target

A capital ship is only protected while enough screens survive alongside it. Strip the screen and torpedoes start reaching the capitals directly. That is why the mod pushes screen production up and why the light cruiser has a screen-killer trim.

Straight answers

What it does not do

A lot of AI overhaul mods are vague about the ceiling. This one is not.

It cannot order a specific fleet anywhere

There is no scripted hook for assigning a mission to a task force. What exists shifts how willing the AI is to run a mission type. Anyone claiming finer control than that is describing something the game does not expose.

It cannot route convoys

Convoy pathing is engine-side. What it can do is make the AI escort, build escorts, and keep its warships out of the water where its convoys are dying.

It does not buff anything

No modified defines, no combat multipliers, no is_ai = yes bonuses. Everything it changes is a priority the AI was already weighing.

It was never run in the game

Built in an environment with no HOI4 installation. Every identifier is verified against real game files and the mod cannot fail to load — but every claim about behaviour is a claim about documented semantics, not an observed outcome.

Verification

HOI4 fails silently, so the mod checks itself

A misspelled strategy type, a region id that does not exist, or a module that was renamed all give you a mod that loads, runs, and does nothing. The only symptom is an ordinary game where the AI still sails into the Channel. So the mod ships with a parser and a validator. 

$ python3 tools/validate.py --strict
  ·  parsed 5/5 script files
  ·  checked 79 ai_strategy entries
  ·  checked 39 region references across 29 regions
  ·  checked 5 design groups and 8 designs

13 checks · 0 errors · 0 warnings

It earns its keep. It caught dp_ship_secondaries before the mod was ever loaded — the module is dp_ship_secondaries_1, but the category you reference in a design is ship_dp_secondaries, and the two are transposed. The distinction it cares most about is that naval_avoid_region takes a numeric strategic region while area_priority takes a named area. Mixing them up produces a strategy that is silently dead.

The mod was authored against vanilla 1.14.1 files, and 1.19 rebalanced the navy — so refresh_tables.py re-derives every table from your own installation, reading map/definition.csv to work out which regions are sea zones. Anything your version renamed becomes an error instead of a design that silently never matches.

Devblog · Sat 15 Aug 2026

The bug was in the thing checking for bugs

The ask was simple enough to state: make the Hearts of Iron IV AI handle its navy properly, including the common sense that as Germany you do not put your fleet in the English Channel, because the Royal Navy's submarines are there and your convoys are not coming back.

Vanilla already knew, and gave up in 1942

The first useful discovery was that this is not a missing feature. Vanilla ships a plan called axis_stay_away_from_the_royal_navy that avoids the Channel at weight 600. Reading its enable block explains everything: it is capped at date < 1942.1.1 and it only holds while Germany's navy is under half of Britain's. Both switches turn it off exactly when it still matters. That reframed the whole job — not "teach the AI a new idea" but "the idea is there and it expires."

Everything I could have guessed, I would have got wrong

The folder for AI ship designs is common/ai_equipment. I built the tree as common/ai_equipment_design, which is a plausible-looking name that exists nowhere. area_priority looks like it takes a strategic region number and takes a named area instead. naval_mission_threshold is inverted — a higher value makes the AI less likely to run the mission, which if you get it backwards silently inverts an entire country file. None of that is guessable. All of it is sitting in the game files with the answers commented next to it: 

ai_strategy = {
    type = naval_avoid_region
    id = 18 #english channel
    value = 600 # avoid doing missions as well
}

Vanilla comments its own region ids. That is ground truth, and it beats any amount of confident forum knowledge.

The validator paid for itself twice

Because the game fails silently, I wrote the parser and validator before writing any mod content. It caught a transposed module name immediately. Then it caught something better.

The mod was built against 1.14.1 files, but the live game is 1.19 and 1.19 rebalanced the navy. So I wrote a tool to re-derive every lookup table from a real installation, including working out which strategic regions are sea zones by reading the province definitions. Deciding that by "are most of this region's provinces sea" seemed obviously right. It is not: 

# region 76 (East China Sea): 27 provinces, 13 sea, 14 not-sea
# region 93 (Banda Sea):     57 provinces, 15 sea, 42 not-sea

Archipelago. Both are sea zones with more islands in them than water, and the careful-looking rule classified them as land — which promptly failed the Japan and United States files, because both route the oil lane through exactly those two regions. The right rule is the blunt one: any sea province at all. Across a 228-region map that adds seven regions and produces no false positives.

The failure I had actually protected against was the mod being wrong. The failure I got was the checker being wrong, and it only surfaced because I tested the checker against real data instead of trusting that it was the sound part.

What I would keep

Building the verification before the content, and writing down which claims are inference rather than fact. Three things in this mod are reasoned rather than verified, and all three are in docs/verification.md with the reasoning and the failure mode. They all fail safe: if the inference is wrong the mod does less than intended, never something wrong. That distinction is worth more than a confident README.
